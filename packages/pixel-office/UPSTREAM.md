### Mechanical rewrite (the only change to upstream files)

Next.js's Turbopack does not map `./x.js` imports to `./x.ts` files (TypeScript does). So the `.js` suffix was stripped from relative imports in `upstream/`:

```bash
find packages/pixel-office/upstream -name "*.ts" -exec sed -i -E "s#(from '\.{1,2}/[^']+)\.js'#\1'#g; s#(import\('\.{1,2}/[^']+)\.js'\)#\1')#g" {} +
```

Re-run it after syncing a newer upstream.

## Agent Town's own code

- `src/loader.ts`: browser asset loader, adapted from upstream `webview-ui/src/browserMock.ts`. It decodes the PNGs and installs them with the engine's setters.
- `src/controller.ts`: `PixelOffice`, the boundary between Agent Town's run state and the engine. It maps statuses to engine calls, fits the occupied part of the layout, and provides name-tag positions and click hit-testing.
- `scripts/build-assets.ts`: generates `asset-index.json` and `furniture-catalog.json` with upstream's `build.ts`.

## Types

`types/` holds declarations generated by `npm run build:types -w @agent-town/pixel-office`. The web app type-checks against them, so vendored code needn't meet the app's stricter compiler settings. Regenerate after changing `src/`.
